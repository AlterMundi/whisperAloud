# WhisperAloud 0.3.0 Field Validation Checklist

Manual, hands-on validation for the 0.3.0 release on a real GNOME/Wayland
desktop (Debian 13, Intel laptop, no NVIDIA GPU). The automated test suite
(`tests/`, `./scripts/test_ci.sh`, `./scripts/test_e2e.sh`, `./scripts/test_gui.sh`)
already covers the code paths; this checklist exists to catch the things only
a real session surfaces — real portal dialogs, a real compositor, a real
microphone, a real Flatpak sandbox — and to double as a feature inventory for
this release.

Built from the source of truth for 0.3.0: `CHANGELOG.md`, `README.md`,
`docs/dbus-api.md`, `docs/flatpak.md`, the CLI parser in `__main__.py`, the
`ui/` GTK4 widgets, `config.py`, and the closed Lattice tickets (`lattice list`
in the repo root).

## How to report a defect

For each failing or partial item, fill in the Result column (`✅` / `❌` / `⚠️`
with a short note) and, for anything other than a clean `✅`, capture:

```
FV id:      FV-0NN
What happened:   <one or two sentences, what you actually saw>
Expected:        <copy the "Expected result" column for this item>
Logs:
  journalctl --user -u whisper-aloud -n 200 --no-pager
  journalctl --user -b 0 | grep -i whisperaloud          # if run outside the unit
  flatpak run --command=sh org.fede.whisperaloud -c 'whisper-aloud status'  # Flatpak only
  flatpak run --verbose org.fede.whisperaloud             # Flatpak only, verbose portal/sandbox trace
Environment: native install / Flatpak, GNOME Wayland version, kernel
```

File it in Lattice from the repo root:

```bash
lattice create --type bug --priority <low|medium|high|critical> \
  --title "FV-0NN: <short summary>" \
  --description "<what happened / expected / logs, as above>"
```

Link the FV id in the title so the result can be traced back to this
checklist. Use `lattice list` / `lattice show <id>` to check it landed.

## Risk legend

Items marked **[FLATPAK-RISK]** are places where Flatpak sandboxing
(portals, no direct X11/Wayland socket, no `ydotool`/`xdotool`/`wl-copy`
inside the sandbox, `/.flatpak-info` detection) can plausibly behave
differently from a native/venv install — run these twice, once per install
method, if both are available.
